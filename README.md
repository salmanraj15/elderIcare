# elderIcare

elderIcare is an experimental acoustic event detection project designed to explore machine-learning approaches for recognizing acoustic events relevant to elder-care environments.

The current implementation is a small development pipeline that loads WAV audio, extracts simple acoustic features, classifies the resulting feature vectors, and evaluates the model using a synthetic dataset.

## Project Status

**Status:** Experimental development

The current implementation provides:

- WAV audio loading
- Audio normalization
- Fixed-duration audio windowing
- RMS energy extraction
- Peak amplitude extraction
- Synthetic dataset generation
- Deterministic stratified dataset splitting
- Neural-network training
- Overall model evaluation
- Per-class model evaluation
- WAV-based inference
- Model saving and loading
- Automated tests

The current classifier is a development baseline and has not been validated on real-world elder-care audio.

## Current Acoustic Classes

The current baseline model supports three classes:

- `background`
- `speech`
- `impact`

These classes represent acoustic events only.

For example, an `impact` prediction does not establish that a person has fallen.

## Current Pipeline

The current development pipeline is:

```text
WAV audio
    ↓
Audio loading
    ↓
Audio preprocessing
    ↓
Fixed-duration windows
    ↓
Feature extraction
    ↓
Acoustic event classifier
    ↓
Predicted event + confidence
```

## Features

The current feature representation contains two numerical features:

- RMS energy
- Peak amplitude

These features are extracted from audio windows.

The implementation is located in:

```text
src/eldericare/features.py
```

## Model

The current model is `AcousticEventClassifier`.

It is a small feed-forward neural network implemented using PyTorch.

The current architecture is:

```text
Input: 2 features
    ↓
Linear(2 → 8)
    ↓
ReLU
    ↓
Linear(8 → 4)
    ↓
ReLU
    ↓
Linear(4 → 3)
    ↓
Output: 3 class logits
```

The model is implemented in:

```text
src/eldericare/model.py
```

## Dataset

The current development dataset is synthetic.

It is generated by:

```text
create_synthetic_dataset()
```

The synthetic dataset contains:

- `background`
- `speech`
- `impact`

The dataset is intended to verify the training and evaluation pipeline.

It is **not representative of real-world acoustic data**.

The dataset utilities are implemented in:

```text
src/eldericare/dataset.py
```

## Training

Training utilities are implemented in:

```text
src/eldericare/train.py
```

The current training configuration uses:

- PyTorch
- Cross-entropy loss
- Adam optimizer
- Learning rate: `0.01`
- Batch size: `32`
- Epochs: `50`

The training pipeline also supports:

- Overall accuracy evaluation
- Per-class accuracy evaluation
- Saving the trained baseline model

## Running Training

Make sure the project's virtual environment is active.

Run:

```powershell
python -m eldericare.train
```

The training script creates the synthetic dataset, performs the train/evaluation split, trains the model, evaluates it, and saves the baseline model.

Example output:

```text
Evaluation accuracy: 100.00%
background: 100.00%
speech: 100.00%
impact: 100.00%
Model saved to: models\baseline.pt
```

The exact evaluation result may change if the dataset, model, training configuration, or random seed changes.

## Inference

Inference utilities are implemented in:

```text
src/eldericare/inference.py
```

### `predict_event()`

`predict_event()` accepts a feature vector containing:

- RMS energy
- Peak amplitude

It returns:

- Predicted event
- Confidence

### `predict_wav()`

`predict_wav()` connects WAV loading and feature extraction to the prediction pipeline.

This allows a WAV file to be passed through the complete inference workflow.

## Command-Line WAV Prediction

A command-line prediction script is available at:

```text
scripts/predict_wav.py
```

Example:

```powershell
python scripts\predict_wav.py path\to\audio.wav
```

## Current Limitations

The current implementation has several important limitations:

- The development dataset is synthetic.
- The synthetic dataset is not representative of real-world elder-care environments.
- The model uses only two simple numerical audio features.
- The current model supports only three acoustic classes.
- Real-world performance has not been established.
- No production audio dataset is currently included.
- No deployed Raspberry Pi inference service is currently included.
- No production alerting system is currently implemented.

## Safety Boundary

elderIcare is an experimental acoustic-event detection system.

The system should not make unsupported claims such as:

- "A person has fallen."
- "A medical emergency is occurring."
- "The person requires medical treatment."

An acoustic event can provide evidence that something may have happened, but acoustic classification alone does not establish the underlying real-world event.

Any future alerting system should communicate uncertainty and, where appropriate, require human verification.

## Privacy

Audio recordings can contain sensitive information.

The project follows a privacy-by-design approach.

Where practical:

- Record only necessary audio.
- Avoid recording private conversations unnecessarily.
- Obtain appropriate consent from people who are recorded.
- Store recordings securely.
- Do not publish private recordings.
- Remove unnecessary identifying information from metadata.
- Keep raw recordings separate from source code.

See `docs/privacy.md` for additional privacy guidance.
